# config-lib v1.4.0: safe hot reload and bounded NOML

**v1.4.0 fixes a hot-reload deadlock, bounds NOML expansion and includes, stops errors from quoting the input, and checks every reloaded file before it replaces the current configuration.** No API is removed or changed in signature, and the default feature set stays on Rust 1.75. Some inputs parse differently or are refused; see "Behavior changes" below.

## What is config-lib?

A multi-format configuration library for Rust. One API for TOML, JSON, INI, XML, HCL, NOML, Java Properties, and CONF, with hot reload, environment variable overrides, schema validation, audit logging, and cached reads.

## Hot reload

- **No deadlock in handlers.** The background watcher dispatched `Reloaded` while it held the configuration's write lock, so a handler that read the new configuration hung the reloader and every reader. Handlers now run after the swap, with no lock held.
- **Checks before the swap.** A reload waits for the file's size and modification time to settle, refuses a file that changed while it was read, and does not let an empty file replace a non-empty configuration (`allow_empty_reload()` allows it). Read-only mode, the defaults table and validation rules carry over; critical validation errors and the new `with_validator(...)` check keep the current configuration and report `ReloadFailed`.
- **Atomic save.** `Config::save_to_file` writes a temporary file and renames it over the target.
- **Fallback that works.** A watcher that cannot start, or stops, polls the file instead of stopping.

## NOML and file loads

- **`${...}` expansion is bounded**: 64 MiB of expanded size, 10,000 references, chains 32 deep, in strict and default NOML. A few hundred bytes could expand to gigabytes before.
- **Includes stay in the config's directory** by default, checked on the canonical path, and config-lib reads them itself so the noml resolver never opens a file.
- **Strict loads for files and hot reload**: `Config::from_file_strict`, `HotReloadConfig::from_file_strict`.
- **File loads refuse non-regular files and files over 16 MiB.**
- All of this is set through the new `LoadOptions`.

```rust
use config_lib::{Config, LoadOptions};

let options = LoadOptions::new()
    .strict(true)
    .allow_include_dir("/etc/app/shared")
    .max_file_size(1024 * 1024);
let config = Config::from_file_with("/etc/app/app.noml", &options)?;
```

## Errors

TOML, NOML, INI, Properties and XML syntax errors are `Error::Parse` with a line, a column and fixed text. They used to quote the offending token, so a password with a missing quote appeared in the error and in hot-reload events.

## Parsing fixes

- INI and environment values `1` and `0` are integers, so `get_or::<u16>` reads them (`get_or::<bool>` still does too).
- Environment overrides keep the type of the value they replace (`APP_DB_PASSWORD=ab,cd` stays a string).
- Without a format, text is CONF unless it is clearly XML, JSON or INI.
- CONF save reads back to the same values.
- HCL is a real parser for the static subset, and refuses expressions it cannot evaluate.
- `Value::as_integer` and `RangeValidator` no longer truncate or saturate floats; `Config::validate` checks nested values; `get_mut` respects read-only mode.
- Audit lines show values as their type and size, and escape every field.

## Behavior changes

- CONF and INI inline comments need whitespace before them: `password = abc#def` keeps `abc#def`.
- CONF refuses text after a value on the same line, keeps `nan`, `inf` and integers too large for `i64` as strings, and reads `[a.b]` as the table `b` inside `a`.
- `Config::from_string` with NOML refuses an include outside the current directory unless `LoadOptions` allows it.

## Dependencies

`serde` and `regex` are removed; neither was used. Direct dependencies: `thiserror`, `dashmap`, `arc-swap`, and `notify` with the default `hot-reload` feature; the format and `async`/`chrono` features add their own as before.

## Upgrade

```toml
[dependencies]
config-lib = "1.4"
```
