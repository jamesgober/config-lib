# config-lib v1.1.0: XML Security Release

**v1.1.0 moves the `xml` feature to `quick-xml` 0.41, which fixes RUSTSEC-2026-0194 and RUSTSEC-2026-0195.** `quick-xml` 0.41 needs Rust 1.79, so the `xml` feature's MSRV moves from 1.75 to 1.79. That MSRV change is why this is a minor release; the default feature set is unchanged and stays on Rust 1.75.

The release also fixes data loss when saving a modified TOML or NOML config, makes the `toml` feature build on its own, and moves the `noml` pin to `=0.9.2`.

## What is config-lib?

A multi-format configuration library for Rust. One API for TOML, JSON, INI, XML, HCL, NOML, Java Properties, and CONF, with hot reload, environment variable overrides, schema validation, audit logging, and lock-free cached reads.

## What's new in 1.1.0

### `quick-xml` 0.31 to 0.41 (`xml` feature)

`quick-xml` 0.31 is affected by RUSTSEC-2026-0194 and RUSTSEC-2026-0195. The dependency is now `quick-xml = "0.41"`, which cannot drift to 0.42 (that release needs Rust 1.86). `From<quick_xml::Error> for Error` now converts the 0.41 error type.

While porting the parser to the 0.41 event API, the XML behaviour was fixed in a few places:

- **Repeated elements become arrays.** `<host>a</host><host>b</host>` used to keep only the last element.
- **Entities, character references and CDATA are resolved.** `&amp;` in text and attributes becomes `&`, and CDATA content is kept instead of dropped.
- **Malformed input is an error.** A document that ends with open elements, or uses an unknown entity, no longer returns a partial result.
- **Deep nesting is an error.** More than 128 nested elements used to overflow the stack and abort the process.

### Saving a modified TOML or NOML config

`Config::serialize`, `save` and `save_to_file` returned the original text of a TOML or NOML file even after `set`, `remove` or `merge`, so changes were silently lost. The preserved text (with comments and formatting) is still used while the config is unchanged; after a change, the current values are written.

### `toml` feature

- `--no-default-features --features toml` did not compile; it only built together with `noml`. It now builds and is tested on its own.
- TOML strings that contain `${`, such as `password = "${DB_PASSWORD}"`, are read as plain text. The noml crate treats `${...}` as interpolation, which is right for NOML but not for TOML.

### `noml` pin `=0.9.0` to `=0.9.2`

noml 0.9.2 makes `${...}` interpolation work in NOML files, merges tables defined in several places, rejects duplicate keys, and fixes its serializer. MSRV for the `noml` and `toml` features stays at 1.82.

### Lockfile

`h2` 0.3.27 (RUSTSEC-2026-0258) and `rustls-pemfile` 1.0.4 (RUSTSEC-2025-0134) are gone from `Cargo.lock`, and `crossbeam-epoch` is at 0.9.21 (RUSTSEC-2026-0204, via `criterion`).

## MSRV

| Features                 | MSRV |
|--------------------------|------|
| default and most opt-ins | 1.75 |
| `xml`                    | 1.79 |
| `noml`, `toml`           | 1.82 |

CI now checks each row on exactly that version.

## Breaking changes

**None in the API.** The `xml` feature needs Rust 1.79, and code that relies on `From<quick_xml::Error>` with the 0.31 error type must move to `quick-xml` 0.41. XML documents with repeated sibling elements now produce arrays instead of the last element.

## Installation

```toml
[dependencies]
config-lib = "1.1"

# With everything
config-lib = { version = "1.1", features = ["json", "xml", "hcl", "noml", "toml", "validation", "async", "chrono"] }

# Slimmest possible
config-lib = { version = "1.1", default-features = false, features = ["conf"] }
```
