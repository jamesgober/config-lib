# config-lib v1.3.1: INI and CONF fixes

**v1.3.1 fixes four ways the INI and CONF parsers misread a file, and parses CONF about twice as fast.** No API changes. The default feature set is unchanged and stays on Rust 1.75.

## What is config-lib?

A multi-format configuration library for Rust. One API for TOML, JSON, INI, XML, HCL, NOML, Java Properties, and CONF, with hot reload, environment variable overrides, schema validation, audit logging, and lock-free cached reads.

## Fixes

### INI read a quoted value's escapes twice

A quoted INI value had its escapes read while it was parsed, and then again as if it were unquoted. `path="C:\\new"` came out as `C:`, a line break and `ew`, not `C:\new`. The second pass also trimmed the spaces at the end of the quoted value. Each value's escapes are now read once, and a quoted value keeps its spaces.

### INI took an apostrophe inside text as a quote

Any `'` or `"` opened a quoted value, wherever it was. `name = O'Brien` read everything up to the next `'` in the file, across lines and keys, into one value. A quote now opens a quoted value only as the value's first character; inside text it is text.

### INI accepted a quote that is never closed

An unclosed quote read the rest of the file into one value. It is now a parse error that names the line the value started on:

```text
Parse error at line 2, column 1: Unterminated quoted value
```

The message does not quote the value, which may be a secret.

### CONF dropped a section named like a key

`db = on` followed by a `[db]` section lost every key in `[db]` without an error: the section's keys had nowhere to go, because `db` already held a value. That is a parse error now. A section that appears twice still continues where it left off, and a section with no keys is still left out.

## Faster CONF

On the 1 KiB benchmark input (twenty sections, eighty keys), a parse made 244 allocations and now makes 124. The time fell from 20-25 µs to 11.5-13.5 µs, measured in a release build with old and new run alternately on the same machine, which was under full CPU load at the time. On an idle machine both numbers are lower; the 1 KiB target in `docs/PERFORMANCE.md` is 10 µs.

Three changes:

- `true`, `yes`, `on`, `false`, `no`, `off`, `null` and `nil` are compared without making a lower-cased copy of every value. The words are ASCII, and no other character lower-cases to one of their letters, so the result is the same.
- A section's name is copied once, not once for each of its keys.
- ASCII text is scanned a byte at a time; other text is still decoded a character at a time, and line and column numbers count characters as before.

## Upgrade

```toml
[dependencies]
config-lib = "1.3"
```

An INI or CONF file that hit one of the fixes reads differently or is refused: a value with `\\` in quotes, a value with an apostrophe in its text, an unclosed quote, a CONF section that reuses a key's name. Every other file reads as before.
