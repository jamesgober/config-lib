# config-lib v1.4.1: noml 0.9.4

**v1.4.1 moves the `noml` pin from `=0.9.2` to `=0.9.4` and keeps noml's new resolver limits in step with `LoadOptions`.** No API change and no new dependencies. The default feature set stays on Rust 1.75; `noml` and `toml` stay on 1.82.

## What is config-lib?

A multi-format configuration library for Rust. One API for TOML, JSON, INI, XML, HCL, NOML, Java Properties, and CONF, with hot reload, environment variable overrides, schema validation, audit logging, and cached reads.

## noml 0.9.4

noml 0.9.4 bounds `${...}` expansion and reference chains in its own resolver, confines includes, keeps document text out of its errors, and no longer saves `env()` values as plain text. config-lib 1.4.0 already guarded against the expansion and include problems in front of the resolver; 1.4.1 takes the fixes in noml too. The parts of noml that config-lib reads (the syntax tree, the error variants and their message prefixes) are unchanged.

## Limits stay in step

noml 0.9.4 checks its own limits on every resolve. config-lib now passes its `LoadOptions` values to the resolver (`noml::Resolver::with_limits`):

| `LoadOptions`          | noml `ResolverLimits`  | Default |
|------------------------|------------------------|---------|
| `max_expanded_size`    | `max_output_bytes`     | 64 MiB  |
| `max_expansions`       | `max_references`       | 10,000  |
| `max_expansion_depth`  | `max_reference_depth`  | 32      |
| `max_includes`         | `max_includes`         | 64      |

A caller who raises a limit is no longer refused by noml's default. config-lib's own check still runs first.

## Clearer errors

When noml's resolver refuses a document, the error is now `Error::Parse` with config-lib's text for the same limit (for example "the document has too many ${...} references" or "too many included files") instead of "syntax error". The line and column are kept; noml's message, which can name a path, is not.

## Upgrade

```toml
[dependencies]
config-lib = "1.4"
```

Code that compiled against 1.4.0 compiles and behaves the same, apart from the error text above.
