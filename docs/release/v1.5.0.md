# config-lib v1.5.0: lists of tables in CONF

**v1.5.0 reads `[[name]]` lists of tables in CONF and keeps a CONF section with no keys, both as TOML does.** No API change and no new dependencies. The default feature set stays on Rust 1.75; `noml` and `toml` stay on 1.82.

## What is config-lib?

A multi-format configuration library for Rust. One API for TOML, JSON, INI, XML, HCL, NOML, Java Properties, and CONF, with hot reload, environment variable overrides, schema validation, audit logging, and cached reads.

## Lists of tables

```conf
[[upstream]]
host = "a"
weight = 2

[[upstream]]
host = "b"
[upstream.tls]
verify = true
```

`upstream` is a list of two tables. The rules are TOML's: the keys after `[[upstream]]` go into the new item, a `[upstream.tls]` or `[[upstream.path]]` header after it belongs to the last item, and an item with no keys is kept. Mixing `[upstream]` and `[[upstream]]`, or `[[upstream]]` with a key or value list of that name, is refused with the header's line and column. The same text read as TOML gives the same value. Before v1.5.0 the header failed on its first line.

## Empty sections

A CONF section header with nothing under it was left out of the parsed value:

```conf
[auth]
key = 1

[auth.passwrd]
```

TOML and NOML give `auth.passwrd` as an empty table; CONF gave nothing, so a caller that checks section and key names never saw the misspelled section. CONF now keeps it as an empty table at its path. A caller that read a missing value for an empty CONF section now reads an empty table.
