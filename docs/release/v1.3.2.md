# config-lib v1.3.2: get_or for plain types

**v1.3.2 makes `Config::get_or` work with plain types, as the README said it did, and makes every README example compile.** No breaking changes and no new dependencies. The default feature set is unchanged and stays on Rust 1.75.

## What is config-lib?

A multi-format configuration library for Rust. One API for TOML, JSON, INI, XML, HCL, NOML, Java Properties, and CONF, with hot reload, environment variable overrides, schema validation, audit logging, and lock-free cached reads.

## Fixes

### `get_or` did not compile for plain types

`Config::get_or` is bounded `V: TryFrom<Value>`, and up to 1.3.1 config-lib implemented `TryFrom<Value>` for no plain type. So the one-line read the README teaches failed to compile:

```rust
let port: u16 = config.get_or("server.port", 8080); // E0277 before 1.3.2
```

`TryFrom<Value>` and `TryFrom<&Value>` are now implemented for `bool`, `String`, `f64`, `i8` to `i64`, `isize`, `u8` to `u64`, and `usize`, with `config_lib::Error` as the error type:

- Integer types accept an integer, a float with no fractional part, or a string that parses as the target type, and are range-checked: `70000` does not convert to `u16`, and `8080.5` converts to no integer type.
- `bool`, `f64`, and `String` follow `Value::as_bool`, `Value::as_float`, and `Value::as_string`.

`get_or` returns the default when the path is missing or the value does not convert.

### README examples did not compile

The quick start called `?` on the `Option` that `Config::get` returns, and several sections used APIs that do not exist. Every example is rewritten against the real API and now runs as a doctest.

## Upgrade

```toml
[dependencies]
config-lib = "1.3"
```

Code that compiled against 1.3.1 compiles and behaves the same.
